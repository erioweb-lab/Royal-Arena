### ① v29: 게임 시작·카드 도감 완전 불능 (치명)
- **증상**: 타이틀 화면의 "배틀 시작"/"카드 도감" 버튼이 아무 반응 없음. 도감 내용도 안 보임.
- **원인**: v29 자동 패치가 `updateProjs` 함수의 **중괄호 1개를 유실** → 게임 JS 전체가 `SyntaxError`로 파싱 실패 → 이벤트 핸들러가 아예 등록되지 않음. HTML/CSS는 그대로라 "화면은 보이지만 아무것도 안 되는" 상태.
- **수정**: v30에서 괄호 복원. `node --check` 게이트 도입.
- **재발 방지**
  1. **모든 배포 전 `node --check` 필수** (스크립트를 추출해 검사 — 문법 오류는 100% 걸린다).
  2. 자동 패치 후에는 **런타임 하니스**(아래 §3)로 실제 클릭 시나리오 검증.
  3. 어설션(패치 검증 문자열)은 **파일에 실제로 삽입된 문자열을 그대로 복사해 대조**한다. 기억/추측으로 작성하면 오타로 패치가 조용히 실패한다(v29 반복 실패 원인: `"'boar':"` ↔ 실제 `"boar:"`).

### ② 도감 라벨 하드코딩 "(12종)" (v30에서 발견)

- **원인**: 카드 수를 HTML에 하드코딩.

- **재발 방지**: 카드 수/목록을 화면 문구에 쓸 때는 **반드시 `DECK.length` 참조**. 하드코딩 금지. 새 카드 추가 시 `DECK` 배열에 키를 넣는 것만으로 모든 라벨이 따라오는지 확인.

  3. 모든 생성 아트는 게임에 넣기 전 위 만화효과 체인을 통과시켜 화풍 통일.

### ④ 진영 배너(플래그)가 유닛을 가림 (v31)
- **증상**: "아군/적군 진영" 배너가 다리 앞길 위 유닛의 머리/상체를 덮음.
- **원인**: 배너가 **화면 공간 오버레이로 유닛 렌더 이후**에 불투명하게 그려지고 있었음.
- **수정**: 배너 블록을 렌더 파이프라인에서 **지형 뒤(타워/유닛 이전)** 로 이동 + 반투명(0.55)·축소(182×52→152×44).
- **재발 방지**: 필드 오브젝트 렌더 순서 규칙 준수 — **지형 → 배너(반투명) → 타워 → 유닛(y정렬) → 투사체 → 이펙트**. 화면 공간 UI를 필드 위에 올릴 때는 반드시 반투명 + "가림 허용 범위" 검토.

### ⑤ 작은 화면에서 스크롤/콘텐츠 잘림 (v32)
- **증상**: 모바일(특히 주소창 등장/해제로 높이가 변하는 동적 환경)과 PC 짧은 창에서 타이틀 하단이 잘리거나 스크롤 필요.
- **원인**: 타이틀 화면이 내부 스크롤(`overflow-y:auto`) 구조인데 도감 그리드 18종(고정 min-height 96px)이 세로 공간을 초과.
- **수정**: 높이 기준 단계적 압축 미디어쿼리(≤780px: 도감 설명 숨김, ≤660px: 히어로 축소·카드 축소, ≤540px: 가로폰 모드 — 이름 숨김·여백 최소화), `100vh→100dvh` 폴백, 스크롤바 숨김(비상시 내부 스크롤은 유지), 전투 화면은 `object-fit:contain` 레터박스로 유지.
- **재발 방지**: 배포 전 **두 뷰포트(모바일 390×844 / PC 1280×800) 무스크롤 프로브** 통과(§3). 새 UI 블록 추가 시 `min-height:0` + 높이 미디어쿼리 압축 규칙을 함께 추가.

## 2. 배포 전 필수 게이트 (순서대로, 하나라도 실패하면 배포 금지)

1. **문법**: 게임 `<script>` 본문 추출 → `node --check` 통과.
2. **런타임 하니스**: 하니스 HTML로 실제 동작 확인 —
   - `ERRS=[]`(window.onerror 0건)
   - 시작 버튼 클릭 → 전장 전환됨(`CANVAS_COLORS>0`)
   - 도감 클릭 → 이미지 N장 렌더(`CODEX_IMGS=18`)
   - 유닛 소환(`spawnCard`) 후 `UNITS` 증가
3. **무스크롤 프로브**: 모바일(390×844)/PC(1280×800)에서
   `document.documentElement.scrollHeight <= clientHeight` (타이틀·전장 각각).
4. **클린 클론 푸시**: `git clone` 원격 → 파일 교체 → 커밋(`erioweb-lab`) → push → `git ls-remote`로 커밋 해시 일치 확인. (로컬 히스토리 불신 원칙 — 원격 전체가 누적 소스.)
5. **Pages 확인**: 45초 대기 → `curl …/sw.js`에서 새 캐시 버전 폴링(최대 3회) → `PAGES_HTTP=200`.
6. **전달**: `index.html`·`sw.js`·변경된 .md를 `genspark_deliver_files`로 전달 + 실기기 확인 포인트 안내.

- 캐논 실전 포격 데미지 수치 실증(하니스 타이밍 문제로 works:false 반복) — 실기기 확인 필요.

### ⑥ v32 이후: 전장에서 타워·유닛이 안 그려지는 화면 (사용자 제보, PC)
- **증상**: 잔디 지형·강·다리와 하단 카드 UI는 보이는데 타워/유닛만 비어 보임.
- **원인(추정)**: 캔버스 드로우 루프 도중 런타임 오류로 루프가 멈춰 지형 뒤 요소(타워/유닛)가 그려지지 않거나, 캐시 갱신 도중 아트 로딩 실패. 환경 의존적이라 하니스에서 재현되지 않음.
- **수정** (v33): `ra-watchdog` 감시자 — rAF 프레임 스톰프 감시(3초 정지 시), 전장 중 window 오류 감지 시 ①복구 오버레이 표시 ②캐시 전량 삭제 + SW 재등록 + 1회 자동 새로고침(세션당 1회, 반복 크래시 시 수동 버튼만 노출).
- **재발 방지**: "화면이 멈추면 사용자가 새로고침해야 한다"는 구조를 금지 — 감시자가 기본 탑재되며, 새 씬/렌더 경로 추가 시 `ra-crash` 이벤트 로그로 재현 여부를 먼저 확인.

### ⑦ 타워 미표시 지속 — 근본 대책 (v34)
- **증상(재발)**: v33 감시자 이후에도 사용자 PC에서 타워가 받침대만 표시(이미지 로드 실패가 환경별로 지속).
- **근본 대책**: ① 이미지 가드를 `complete` → `complete && naturalWidth>0`로 강화 ② 7초 후에도 로드되지 않은 타워 이미지는 **절차적 석재 타워(캔버스 드로잉)로 자동 교체** — 로딩 실패와 무관하게 타워가 항상 보임 ③ 유닛 스프라이트 가드도 동일 강화.
- **재발 방지**: 배포 게이트에 "이미지 로드 실패해도 게임 화면이 성립하는지" 추가. 아트 의존 요소는 절차적 폴백 필수.
- **유닛 이미지 화풍**: v31 후처리가 기존 3D 화풍과 어긋나 어색했다 → §11 프롬프트 가이드(3D 스타일·림라이트·투명 컷아웃)로 재생성, 후처리는 알파 엣지 정리만 적용.

### ⑧ v34: 도감 비움·배틀 시작 불능 재발 (v35에서 수정)
- **원인**: 아트 오버라이드 코드를 `<script>` 태그 없이 본문에 삽입(텍스트 노출·미실행)+삽입 과정에서 `ART` 병합 루프 소실.
- **수정**: script 블록 감싸기 복원, 병합 루프 복구, 이미지 맵 오염 제거.
- **재발 방지**: 스크립트 삽입은 완전한 `<script>…</script>` 블록으로. 삽입 후 모든 script 블록을 개별 `node --check` + 하니스로 도감 개수·시작 클릭 확인 후 배포.

### ⑨ 전수 감사 발견: 스프라이트 병합 루프 누락 (v36에서 복원)
- **증상**: 신규 유닛(발키리·멧돼지 등)이 스프라이트 대신 절차적 폴백 도형으로 그려져 "다른 유닛과 어색함".
- **원인**: v34~35 아트 삽입 과정에서 `for(const nk in ART_SPR_NEW) ART_SPR[nk]=…` 라인 소실(말미 오버라이드가 SPR에 직접 넣어 부분 보완했으나 로드 시점·도감 경로 불일치).
- **복구**: 병합 루프 복원 + 전 script 블록 개별 `node --check` + 동기식 하니스(캡처 타이밍 문제 해결: 클릭·소환을 스크립트 실행 시점에 즉시 수행)로 런타임 확인.
- **재발 방지**: 아트 관련 3개 맵(ART/ART_SPR/ART_TOW)과 병합 루프 2줄은 배포 게이트 고정 점검 항목으로 등록(§2 게이트 1.5단계).

### ⑩ 전수 감사 발견: 장식·지물 선언 소실 (v37에서 복원)
- **증상**: 정적 지형 장식(용암·얼음 테마 지물 등)이 일부 환경에서 안 보이거나 정적 레이어가 조용히 실패(FIELD_IM.onload의 try/catch가 오류를 삼킴).
- **원인**: v34~35 아트 삽입 과정에서 `const ART_DECO`/`const ART_GDEC` 선언이 참조보다 뒤로 밀리거나 소실(TDZ/ReferenceError) — 실행이 그 지점에서 중단되면 이후 초기화 전부 미실행.
- **복구**: 선언을 첫 참조(const DSPR=) 앞에 복원 + 스텁 헤드리스 실행(vm)으로 전체 스크립트가 끝까지 도는지 확인하는 검증 도입(EXEC_OK·DECK/CARDS/SPR/TSPR 키 수·spawnCard·update 프레임).
- **재발 방지**: 배포 게이트에 "스텁 헤드리스 EXEC_OK + 맵 키 수 점검" 추가. try/catch로 삼켜지는 오류(그리기 실패)를 신뢰하지 말 것.

### ⑪ 도감 그리드 빌더 소실 + "업데이트 안 된 듯한" 혼동 (v38)
- **증상**: 도감 버튼 아래 카드 목록이 없음. 사용자는 "index.html이 안 바뀐 듯하다"고 보고(실제 라이브는 최신 — md5 동일, 화면 라벨도 신규).
- **원인**: v34~35 사고로 **도감 그리드를 만드는 JS 빌더가 소실**(백업에도 부재 확인 → 확정 스펙으로 재작성). 혼동 원인은 SW cache-first + 버전 표시 부재.
- **복구**: 빌더 재작성(ART 18종 카드아트+이름+코스트 렌더), SW 내비게이션 **network-first**(온라인 새로고침 시 항상 최신), 하단 **버전 칩(vN)** 표시로 내가 보는 버전을 즉시 확인 가능.
- **재발 방지**: 배포 게이트에 ① codex 빌더 존재 ② 스텁 헤드리스 EXEC_OK ③ 버전 칩 bump 추가. 삽입 작업 후 라이브 스냅샷과 라인 비교.

### ⑫ 18장 도감 그리드로 타이틀 세로 넘침 (v39)
- **증상**: 도감 6열×3행+설명 칩 구조가 모바일 세로 공간을 초과해 하단(버전 칩 포함) 잘림.
- **복구**: 그리드를 9열×2행 소형 셀로 재구성(설명 숨김·이름 ellipsis·간격 축소, 높이 단계 쿼리 수치 하향).
- **재발 방지**: 카드 수가 늘면 그리드는 행 수 기준(18→9×2, 24→12×2)으로 계산해 배치. 배포 게이트의 동기 레이아웃 측정(SH≤CH)으로 항상 확인.

### ⑬ 타워·유닛 미표시의 최종 원인 — 렌더 루프가 조건부 블록에 갇힘 (v42)
- **증상**: 타워가 패드만 보이고 유닛이 안 그려짐(v32 이후 지속, 환경 무관).
- **원인**: v31 배너 블록 이동 수술에서 `if(S.clash&&S.clash.a>0){` 여는 줄이 타워/유닛 draw 루프 **앞**으로 밀려남 → 루프가 clash 블록 내부에 갇혀 교전 링이 활성화되는 순간에만 렌더됨. 스텁 실행은 오류가 아니라 "정상 스킵"이라 탐지 불가.
- **교훈**: 이동/치환 후에는 **문법만이 아니라 실행 순서 구조**(조건문 열기-본문-닫기, 루프 소속)를 반드시 검증할 것. 배포 게이트에 "draw 순서 어설션(rubble<tower<unit<ambient<clash)" 추가.
- **복구**: clash 여는 줄을 본문(const cx2=…) 앞으로 되돌리고 루프를 최상위로 복원 — 순서 어설션 통과 후 배포.

### ⑭ 부분 수술의 한계 — 검증된 버전 통복원 (v43)
- **경과**: v31 이후 렌더 블록 부분 치환이 사용자 환경에서 반복 실패(종횡비 왜곡·렌더 오류·미표시 혼재).
- **방법 전환**: v30(사용자 화면에서 타워·유닛 렌더가 확인된 마지막 버전)의 `drawTower~drawVignette` 블록을 원본 그대로 복원하고, 승인된 개선(배너 반투명 0.45·152×44)과 요소별 try/catch 격리(한 요소 실패가 전체 렌더를 죽이지 않음)만 최소 적용.
- **진단 개선**: 두 화면 모두에서 보이는 상시 버전 칩(좌하단 vNNN)으로 사용자 보고 버전 식별.
- **재발 방지**: 렌더 경로 수정은 통블록 복원+최소 패치 원칙. 부분 치환 금지.

### ⑮ v43 텍스트 앵커 복원의 잔여 조각 (v44)
- **원인**: 짧은 텍스트 앵커(drawVignette();\n})이 예상과 다른 위치에서 매칭되어 draw() 닫힘이 어긋남(Unexpected token }).
- **복구**: v30 블록을 정의행 기준 동적 경계로 재교체 + 순서 어설션(잔해<타워<유닛<배경<교전<입력) 통과.
- **재발 방지**: 대형 블록 교체는 정의행 기준 동적 경계 원칙(짧은 텍스트 앵커 금지).

### ⑯ 사용자 PC에서 이미지 decode 실패 확정 (v45)
- **증상**: v44 칩이 뜨는 환경에서도 타워는 그림자·체력바·숫자만, 유닛은 그림자·체력바만 표시(스프라이트 전무).
- **원인**: v44 통복원이 v30의 약한 가드(complete만 확인)를 되돌려 놓음 — 사용자 PC에서 타워/유닛 data-URI 이미지가 complete=true·naturalWidth=0으로 깨져 drawImage가 실패, try/catch 격리가 폴백 없이 스킵만 보장.
- **복구**: 가드 3곳에 naturalWidth>0 재적용 — 깨진 이미지는 무조건 절차적 폴백(석재 타워·벡터 유닛)으로 그려짐.
- **재발 방지**: v30 블록을 다시 통째로 넣을 때도 **가드/복구 패치를 항상 재적용**하는 체크리스트 항목화.

### ⑰ "decode 성공·빈 픽셀" 이미지 — 최종 차단 (v46)
- **확정**: v45 칩 환경에서 유닛 폴백(벡터)은 그려지고 타워만 빈 패드 → 타워 PNG가 사용자 PC에서 decode는 되지만 픽셀이 비어 렌더되는 것.
- **차단**: 로드 후 모든 타워/유닛 이미지를 오프스크린 캔버스에 1회 렌더해 **픽셀 유무를 검사** — 정상이면 검증된 캔버스로 원본 교체(이후 drawImage는 브라우저 PNG 경로를 우회), 빈 이미지는 `__valid=false`로 폴백 강제.
- **재발 방지**: 어떤 환경에서도 "이미지가 통과했는데 안 보인다"는 상태가 존재할 수 없게 됨 — 신규 이미지 맵 추가 시 이 사전검증 목록에 등록할 것.

### ⑱ 진단 전환 — 사용자 기기에서 직접 확인 (v47)
- **배경**: 원격 하니스로는 재현 불가(샌드박스에선 항상 정상). 사용자 환경에서 어느 지점이 실패하는지 화면에 직접 표시하기로 함.
- **도구**: 좌상단 진단 HUD `T=x/6 SPR=y/18 drawT=n drawU=n SKIP=n` — 이미지 통과 수·draw 함수 실호출 수·예외 수. 실패 서명: T=0이면 이미지 전멸(폴백 분기), T=6인데 화면 비면 drawImage 무음 실패(캔버스 검증본으로 우회된 상태), drawT=0이면 렌더 루프 사망.
- **재발 방지**: 향후 환경 의존 렌더 문제는 진단 HUD를 먼저 붙이고 수치로 확정한 뒤 수정.

### ⑲ 진단 확정 — 이미지 맵 초기화 전 최상위 크래시 (v48)
- **증상 서명**: 사용자 HUD `T=0/0 SPR=0/0 drawT=685 drawU=201 SKIP=886` — TSPR/SPR 맵이 아예 비어 있고(카드 ART는 멀쩡) 모든 draw 호출이 예외로 끝남(685+201=886 정확히 일치).
- **해석**: 게임 초기화가 이미지 맵 생성 단계 이전에 최상위 크래시(브라우저 고유), 함수 선언은 호이스팅되어 렌더 루프는 살아 있음 → 매 프레임 예외.
- **조치**: ① window error 캡처해 INIT_ERR 메시지+줄번호 화면 표시 ② drawTower/drawUnit 본문 호출 단위 try/catch로 맵이 비어도 절차적 폴백(돌탑·벡터 유닛) 강제 렌더.
- **재발 방지**: 최상위 초기화 크래시는 호이스팅 때문에 "기능은 도는데 화면이 빈" 증상으로 위장 — 초기화 추가 시 화면 오류 표시기 동반 탑재.

### ⑳ 폴백 본문의 보조함수 의존 제거 (v49)
- **진단 해석**: v48 HUD `T=0/0 drawT=1440 SKIP=0` — 맵이 비어 절차적 폴백이 매 프레임 실행되지만, 내부에서 보조함수(사용자 환경에서 미정의) 참조로 매번 예외 → v48의 내부 catch가 삼켜 SKIP=0, 빈 패드로 보임.
- **조치**: drawTower 최우선 분기로 **ctx 기본 도형만 사용하는 자가식 폴백 타워**(그림자·몸체·총안·지붕·왕관·체력바)를 삽입 — 이미지가 없거나 깨진 환경에서는 보조함수를 전혀 거치지 않고 그려짐. 내부 catch는 첫 예외 메시지를 PE로 화면 표시.
- **재발 방지**: 폴백 코드는 외부 보조함수 없이 자가 완결 원칙(기본 ctx 프리미티브만).

### ㉑ 유닛 폴백 안전화 — 스프라이트 참조 예외 차단 (v50)
- **진단**: v49 성과 확인(타워 자가 폴백 렌더 성공 — 사용자 화면에 절차 타워 표시). 잔여 문제: `PE=SPR is not defined` — SPR 미정의 환경에서 drawUnit의 스프라이트 참조 예외가 벡터 폴백 본문까지 중단(유닛 미표시).
- **조치**: drawUnit 내 모든 SPR 접근을 typeof 가드로 안전화 → 스프라이트 유무와 무관하게 벡터 폴백 유닛 항상 렌더. HUD에 MAPS(초기화 시점 맵 존재 S/T/A) 표시 추가.
- **재발 방지**: 폴백 본문 내 전역 참조는 전부 typeof 가드 원칙(⑳ 확장).

### ㉒ 대형 스크립트 블록 분할 (v51)
- **근거**: 사용자 환경에서 카드 아트(블록 앞쪽 데이터)는 렌더되나 SPR/TSPR 맵이 아예 미생성(T=0/0 SPR=0/0) — 샌드박스에선 항상 정상이므로 브라우저별 대형 단일 스크립트 블록 처리 한계로 추정.
- **조치**: 메인 블록을 ①카드·스프라이트 데이터+병합 ②타워·지물 데이터+이미지 맵 빌더 ③게임 로직 — 3개 소형 블록으로 분할(단일 HTML 유지). 한 블록이 죽어도 나머지는 살아 아트가 뜨고, 폴백이 나머지를 보장.
- **재발 방지**: 대량 base64 아트 추가 시 하나의 블록에 몰아넣지 말고 기능별 블록으로 분할 유지.

### ㉓ v51 분할 회귀 복구 + 소실된 스프라이트 맵 빌더 복원 (v52)
- **진단 1(회귀)**: v51 chunk1이 `<script>` 태그 텍스트로 시작(분할기가 태그 경계를 JS에 혼입) → 브라우저에서 chunk1 전체 파싱 실패 → CARDS/ART/ART_SPR 병합 소실. 게이트 미통과 push가 원인.
- **진단 2(근본)**: 헤드리스 PROBE 재검증에서 main 블록에 SPR/TSPR 빌더가 아예 없음을 확정 — v44의 v30 블록 통복원 때 `const SPR={}…`(v30 354행)/`const TSPR={}…`(350행)이 누락됨(DSPR/GSPR/PSPR/ASPR/DIESPR는 존재). 이 때문에 v34 오버라이드 블록의 SPR 병합이 매번 ReferenceError(사용자 HUD `PE=SPR is not defined`의 실체)였고, 유닛·타워 생성형 스프라이트는 어떤 브라우저에서도 렌더될 수 없었음(사용자 T=0/0 SPR=0/0의 근본 원인).
- **조치**: ① esprima 최상위 문장 경계 기준 7청크(≤900KB) 재분할 — 전 블록 node --check ② v30에서 빌더 문장을 원문 그대로 복원해 별도 소형 블록으로 청크 직후 삽입(SPR←ART_SPR, TSPR←ART_TOW, RART 데이터 포함) ③ 각 청크 'use strict' 재부여 ④ PROBE 게이트(맵 카운트=데이터 소스 카운트 일치, SPAWN, FRAME30) 통과 후에만 push.
- **재발 방지**: 스크립트 재배치 시 데이터 선언↔소비자 대응 점검 — ART_* 데이터마다 대응 맵 빌더가 존재하는지 헤드리스 게이트가 자동 검증.

### ㉔ 스펠 연출 고도화 + 절차 합성 BGM (v54)
- **내용**: 파이어볼 주문에 목표 지점 경고 원(빨간 점선 링, 비행 중 표시)·대형 유성 그래픽(54px)·강화 폭발(흔들림 0.5·불티 22개·충격 링) 적용. 번개 주문에 3중 절차 낙뢰 볼트(zapx)+파편 강화. 프린스 돌진 충전 중 화염 잔상, 근접 타격 스파크 추가. 전투 BGM(WebAudio 절차 루프 — 베이스 라인+하이햇, 4박 저음, 음소거 연동, startMatch/finish 훅) 신설.

### ㉕ 변환 스택 누수 — 칩은 1.01x인데 화면은 계속 줌인 (v117)
- **증상**: 파이어볼 타격 후 추가 줌인되고, 이후 칩 표기는 1.01x로 돌아왔지만 화면은 줌인 상태 유지(사용자 제보 + 스크닛 판독).
